## 0. 공통 원칙 (매체 무관)

1. **모든 페이지에 시각 요소 1개 이상.** 텍스트만 있는 페이지는 기억되지 않는다.
2. **색은 지배시킨다.** 1색이 시각 비중 60~70%, 보조 1~2색, 날카로운 액센트 1색. 모든 색을 동등하게 쓰지 않는다.
3. **팔레트는 주제에서 나온다.** 그 팔레트를 완전히 다른 보고서에 그대로 옮겨도 어울린다면, 아직 선택이 덜 뾰족한 것이다. 기본값 파랑으로 도망가지 않는다.
4. **모티프 1개를 정하고 전 페이지 반복.** 둥근 이미지 프레임, 색 원 안의 아이콘 등. 단 색 바/액센트 스트라이프는 모티프로 쓰지 않는다 (아래 금지 목록).
5. **일관성 아니면 포기.** 한 페이지만 꾸미고 나머지를 방치하지 않는다. 전부 꾸미거나 전부 담백하게.

## 1. 절대 금지 목록 (AI 티가 나는 표식)

pptx 원문의 Avoid 리스트. 새 보고서 포맷에서 이건 규칙으로 박아둔다.

- **제목 밑 액센트 라인 금지.** AI 생성 슬라이드의 대표 표식. 여백이나 배경색으로 구분한다.
- **장식용 색 바 / 액센트 스트라이프 전면 금지.** 페이지 폭을 가르는 헤더·푸터 바, 한쪽 가장자리의 세로 사이드바 줄, 카드 한쪽 모서리의 얇은 강조선, 사각형의 "한 변만 테두리" 전부 해당. 카드를 구분하려면 은은한 배경 틴트, 드롭섀도우, 아이콘을 쓴다.
- **본문 가운데 정렬 금지.** 문단과 리스트는 좌측 정렬. 가운데 정렬은 제목만.
- **같은 레이아웃 반복 금지.** 컬럼형, 카드형, 콜아웃형을 섞는다.
- **크림/베이지 기본 배경 금지.** 지정이 없으면 흰색(`FFFFFF`) 또는 브랜드 팔레트. `F5F5DC`, `FAF0E6`, `FAEBD7`, `FFF8E1` 류의 웜뉴트럴 기본값을 쓰지 않는다.
- **저대비 금지.** 텍스트뿐 아니라 아이콘도 배경 대비를 확보한다.
- **넘치는 텍스트 출고 금지.** 안 들어가면 폰트를 줄이거나, 페이지를 나누거나, 컨테이너를 키운다. 잘린 채로 내보내지 않는다.
- **간격 난입 금지.** 0.3" 또는 0.5" 중 하나를 정하고 끝까지 그것만 쓴다.
- **이모지 가구 금지.** 이모지를 불릿·접두사·카테고리 마커로 쓰지 않는다.

## 2. 타이포 스케일

pptx 원문 기준. 문서/HTML에도 비율 그대로 이식 가능.

| 요소 | 크기 |
|---|---|
| 페이지 제목 | 36~44pt bold |
| 섹션 헤더 | 20~24pt bold |
| 본문 | 14~16pt |
| 캡션 | 10~12pt, 흐린 색 |

- 제목과 본문의 **크기 대비를 아끼지 않는다.** 제목이 36pt 미만이면 14~16pt 본문과 구분되지 않는다.
- **폰트는 렌더링 환경이 결정한다.** 파일에 쓴 폰트 이름은 수신자의 뷰어가 렌더링한다. 폭이 다른 대체 폰트로 치환되면 내 화면에서 맞던 글자가 상대 화면에서 넘친다.
  - 안전 폰트 (QA에서 실폭 그대로 렌더 + Office 기본 동봉): Arial, Calibri, Cambria, Times New Roman, Courier New, Bookman Old Style, Century Schoolbook.
  - 리스크 없이 개성을 주는 조합: 안전 목록의 세리프 헤더(Cambria / Bookman Old Style / Century Schoolbook) + 안전 목록의 산세리프 본문(Calibri / Arial).
  - QA 신뢰 불가 (대체 폰트 폭이 달라 넘침 검사가 틀릴 수 있음): Georgia, Trebuchet MS, Impact, Arial Black, Garamond, Consolas, Palatino Linotype, Calibri Light. 제목·액센트에만 쓰고 컨테이너에 약 10% 여유를 준다.
  - **Aptos 기본값 금지.** 2023년 이후 Office 기본 폰트지만 대체 폰트가 없고 구버전 Office에는 아예 없다.
- **한글 보고서**: 위 원칙(안전 폰트 + 폭 여유 10%)을 그대로 적용하되, 본문은 시스템 기본 산세리프 계열로 고정하고 웹 폰트 미로딩 시 폴백을 반드시 지정한다.

## 3. 여백과 레이아웃

- 최소 마진 0.5" (페이지 가장자리에서).
- 콘텐츠 블록 사이 0.3~0.5", 한 값으로 통일.
- 요소가 0.3" 미만으로 붙으면 붙은 것으로 본다.
- 빈 공간을 남긴다. 전 영역을 채우지 않는다.

레이아웃 선택지 (돌려쓴다):
- 2단 (좌 텍스트, 우 도해)
- 아이콘 + 텍스트 행 (색 원 안 아이콘, 굵은 헤더, 아래 설명)
- 2x2 / 2x3 그리드 (한쪽 이미지, 반대쪽 콘텐츠 블록 격자)
- 하프블리드 이미지 (좌 또는 우 전체) + 콘텐츠 오버레이

데이터 표시:
- 큰 수치 콜아웃 (숫자 60~72pt, 아래 작은 라벨)
- 비교 컬럼 (전/후, 장/단, 옵션 나란히)
- 타임라인 / 프로세스 플로우 (번호 스텝, 화살표)

## 5. 표(시트) 규칙 - xlsx 유래

숫자를 다루는 보고서라면 시트든 HTML 표든 이 규약을 그대로 쓴다.

**셀 색 규약 (금융 모델 표준):**
- 파랑 `0,0,255`: 하드코딩 입력값, 시나리오 레버
- 검정: 수식으로 계산된 값
- 초록 `0,128,0`: 같은 파일 다른 시트 참조
- 빨강 `255,0,0`: 외부 파일 참조
- 노랑 채움 `255,255,0`: 핵심 가정, 사용자가 채워야 할 셀

**숫자 서식:**
- 통화 `$#,##0`, 단위는 헤더에 명시 (`매출 (백만원)`)
- 0은 `-` 로 표시, 퍼센트에도 동일: `$#,##0;($#,##0);-`
- 음수는 괄호
- 퍼센트 `0.0%`, **분수로 저장** (`0.15` → `15.0%`. `15`를 넣으면 `1500.0%`)
- 배수는 `0.0x`
- 연도는 텍스트 (`"2024"`, `2,024` 아님)

**구조:**
- 가정은 각자 라벨된 셀 하나에 두고, 수식이 그 셀을 참조한다. `=B5*(1+$B$6)` 이지 `=B5*1.05` 가 아니다.
- 전 기간에 걸쳐 수식을 동일하게 유지한다. 행 중간의 한 셀만 손댄 것이 가장 흔한 조용한 오류다.
- 0이 될 수 있는 분모는 가드한다.
- **모든 가정과 하드코딩 숫자는 읽는 사람이 보는 자리에 출처를 적는다.** 셀 메모 또는 표 끝의 인접 셀. 실제 출처가 있으면 인용한다 (`출처: 2024 결산, p.45`). 사용자가 준 숫자면 그렇게 적는다.
- 채워넣게 할 양식이면 어느 셀을 편집하는지 알려주는 짧은 범례 + 예시 형식을 보여주는 현실적인 값 1행을 넣는다.
- **기존 파일을 편집할 때는 그 파일의 관례가 이 규칙 전부를 이긴다.** 입력 셀(다른 글자색·채움·음영으로 표시됨)을 먼저 찾고 거기에만 쓴다.

## 6. 차트 규칙

pptx 차트 항목에서 일반화. 매체와 무관하게 적용.

- **기본 차트는 벌거벗은 상태로 렌더된다.** 제목 없음, 데이터 라벨 없음, 낡은 팔레트. 매번 다음을 명시적으로 켠다: 제목, 데이터 라벨(+위치), 팔레트 색 지정.
- 프레임은 조용하게: 축 라벨 색을 낮추고, 값축 그리드라인은 얇게, 범주축 그리드라인은 없음, 단일 시리즈면 범례 없음.
- **네이티브 차트를 유지한다.** 렌더된 이미지로 대체하지 않는다. 네이티브 형식이 없는 유형(생키, 네트워크, 코드)만 이미지로 들어간다.
- 누적 막대/컬럼에서 데이터 라벨 위치는 안쪽(`ctr`/`inEnd`/`inBase`)만. 바깥쪽은 파일을 깨뜨린다.

## 7. 출고 전 QA (필수 3단계)

pptx의 QA 절차를 매체 무관 형태로 옮긴 것. **첫 렌더는 항상 실제 결함을 몇 개 갖고 있다.** 찾아서 고치고, 고친 페이지만 다시 렌더하고, 멈춘다.

### 7-1. 콘텐츠 QA
- 텍스트를 플레인으로 덤프해 누락, 오타, 순서 오류를 본다.
- **템플릿 잔재 검색:** `xxx`, `lorem`, `ipsum`, `TODO`, `[insert`, "이 페이지 레이아웃은..." 류. 하나라도 걸리면 고치기 전에는 완료가 아니다.
- 템플릿 슬롯 수 ≠ 실제 항목 수. 템플릿이 4명을 보여주는데 3명이면 4번째의 **그룹 전체**(이미지 + 텍스트박스)를 지운다. 텍스트만 지우면 시각 요소가 고아로 남는다.

### 7-2. 파일 QA
- 수식이 있으면 **재계산을 돌려 오류가 0인지 확인한다.** `#REF!`, `#DIV/0!`, `#VALUE!`, `#N/A`, `#NAME?` 스캔.
- **재계산 통과는 수식이 "평가된다"는 증명이지 "맞다"는 증명이 아니다.** 범위가 한 칸 밀렸거나 잘못된 행을 참조해도 파일은 깨끗하고 숫자만 틀린다. 그리드를 전개하기 전에 수식 2~3개를 먼저 쓰고 기대값을 뽑는지 확인한다.
- 링크·참조는 **실제로 따라가서** 확인한다. 구조 변경 때 조용히 깨진다.

### 7-3. 비주얼 QA
페이지를 이미지로 변환해 전부 눈으로 본다. 생성 코드를 오래 본 뒤에는 렌더된 것이 아니라 기대한 것이 보이므로, 가능하면 다른 사람(또는 서브에이전트)이 새 눈으로 본다. 볼 것:

1. **텍스트 넘침 또는 잘림. 이것부터 본다.** 가장 흔하고 항상 사용자에게 보인다.
2. 요소 겹침 (도형을 관통하는 텍스트, 글자를 가로지르는 선, 겹쳐 쌓인 요소)
3. 출처 표기나 푸터가 위 콘텐츠와 충돌
4. 요소 간 간격 0.3" 미만, 카드/섹션이 거의 닿음
5. 불균등한 간격 (한쪽은 텅 비고 한쪽은 빽빽)
6. 페이지 가장자리 마진 0.5" 미만
7. 컬럼이나 유사 요소의 정렬 불일치
8. 저대비 텍스트 (크림 배경 위 연회색 등)
9. 텍스트 교체 후 어긋난 템플릿 장식 (한 줄 기준으로 배치된 제목 밑줄인데 제목이 두 줄로 줄바꿈된 경우 등)
10. 저대비 아이콘 (대비되는 원 없이 어두운 배경 위 어두운 아이콘)
11. 텍스트박스가 너무 좁아 과도하게 줄바꿈
12. 남은 플레이스홀더

**수정 후에는 렌더 파이프라인 전체를 다시 돌린다.** 중간 산출물(PDF 등)을 재생성하지 않으면 이미지에 변경이 반영되지 않는다.

## 8. 릴리스 게이트

아래가 전부 체크되기 전에는 "완료"라고 하지 않는다.

- [ ] 팔레트가 주제 특정적이고, 지배색 1 / 보조 1~2 / 액센트 1 구조를 지킨다
- [ ] 금지 목록(1장) 위반 0건, 특히 제목 밑 액센트 라인과 색 바
- [ ] 모든 페이지에 시각 요소가 있고, 레이아웃이 최소 3종 이상 섞였다
- [ ] 타이포 스케일이 4단계(제목/섹션/본문/캡션)로 일관되고, 본문은 안전 폰트다
- [ ] 마진 0.5" 이상, 블록 간격이 한 값으로 통일됐다
- [ ] 표의 색 규약과 숫자 서식이 전 시트에 동일하게 적용됐다
- [ ] 모든 가정·하드코딩 숫자에 출처가 인접해 붙어 있다
- [ ] 차트에 제목·데이터 라벨·팔레트 색이 명시적으로 지정됐다
- [ ] 콘텐츠 QA / 파일 QA / 비주얼 QA 3단계를 모두 돌렸다
- [ ] 템플릿 잔재 grep 결과가 비어 있다
